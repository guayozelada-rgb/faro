# Permisos propios de Faro

Un archivo `.toml` por dominio, con un permiso por comando (spec F0 §5.3):

- `engine.toml` (T5): `allow-engine-status`, `allow-engine-restart`.
- `vault.toml` (T6): `allow-vault-list-keys`, `allow-vault-add-key`, `allow-vault-test-key`, `allow-vault-delete-key`.
- `engine.toml` (F1a T8): `allow-engine-call`.
- `wp_plugin.toml` (F1a T8): `allow-wp-plugin-export`. `tauri-plugin-opener` se usa solo desde Rust: ningún permiso `opener:*`.
- `agents.toml` (F1b T5): `allow-agents-pause-all`, `allow-agents-resume-all`, `allow-agents-control-state`. Sin permisos de eventos nuevos: la interfaz escucha `engine://agents` con `core:event:allow-listen` y no puede emitirlo.

Cada permiso nuevo se agrega también a `capabilities/main.json` en la misma tarea que crea el comando.

Además, cada comando se declara en `COMMANDS` de `acl_checks.rs` (incluido en `build.rs`). Con esa lista tauri-build crea siempre el manifiesto `__app-acl__`, de modo que Tauri aplica el control de acceso a los comandos propios aunque falten estos `.toml`. `build.rs` hace fallar la compilación si `COMMANDS`, `register_commands` (`src/lib.rs`), estos `.toml` y `capabilities/main.json` no coinciden.

`autogenerated/` lo regenera tauri-build en cada compilación (`allow-*`/`deny-*` con los mismos comandos) y está ignorado por git. No se edita a mano; los permisos que valen son los de este directorio, que tienen prioridad al tener el mismo identificador.
